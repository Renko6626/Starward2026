# 展示模式、排期冻结与管理员展示资料

日期：2026-11-10。状态：用户已确认业务规则与具体技术方案，并授权开始本地实施。本文不代表功能已实现或部署。

## 意图与已确认规则

活动将进入公开展示阶段，需要固定每个坑位对应的作者，同时持续整理最终作品的公开内容。

- 沿用当前排期并冻结修改，不另外复制一份展示名单。展示模式下不能加入、删除或更换坑位里的作者。
- 作者投稿文件、完整版本和审稿意见继续用于审核与归档，不直接变成公开附件。
- 管理员参考作者最终在 Bilibili 发布的版本，独立上传、编辑用于本站展示的资料。
- 新增独立展示资料；每个坑位最多一行。展示资料中的预览图供时间表和其他展示位置使用。
- 展示形式三选一：图片集、Markdown 文章、Bilibili 视频。不做混排。
- 管理员手动公开。审核通过、作者确认发布或到达排期时间，都不自动公开。
- 原 B 站链接继续保留；作品类型与展示形式分别表达，例如音乐作品使用视频展示形式。

下文标为“建议”的字段、接口及实现细节随整份设计获得确认；未包含的架构扩展仍需另行确认。

## 路线与取舍

排期选择直接冻结现有记录，复用已有 ID、作者关联与时间表。独立名单快照会增加两份数据的维护，本次不采用。

展示资料选择现有 D1 中的一张新表；“新的库、每坑位一行”按新数据表理解，不新增 D1 数据库实例。将正文继续写入 `project_drafts` 会与审核通过时的资料投影混用，因此新增展示资料表，投稿与展示分别维护。

继续使用 React、TanStack Router、Hono、D1、私有 `WORK_FILES` R2 和现有管理权限。建议新增 `react-markdown` 与 `remark-gfm` 渲染文章，支持常用 Markdown、表格和脚注，不启用原始 HTML。

展示图片使用同一私有 R2 桶中的独立目录，Worker 按展示资料的引用及公开状态提供读取；无需公开整桶或新增对象存储服务。

不增加视频上传或转码、富文本编辑器、内容块编排、展示版本历史、定时发布、自动同步 B 站、请求恢复队列、图片处理后台或新常驻服务。

## 排期冻结

建议在 `schedule_versions` 增加可逆的冻结标记。由管理员在现有排期管理中手动进入展示模式，冻结当前生效排期；特殊更正需先明确解除冻结。迁移不自动冻结生产排期。

冻结保护的是排期结构与作者归属，包括坑位增减、认领、换位、释放、报名占位或撤回引起的归属变化，以及管理员分配、改时间、隐藏席位或替换生效排期。后台资格调整如果会使已排入作者从公开排期消失，也应拒绝并提示先解除冻结。

服务端对这些真实写入口统一检查冻结状态；前端同步去掉或禁用不允许的操作。保留现有开放窗口，不通过关闭窗口模拟冻结，也不批量把所有席位改成 `completed`。展示内容、联系资料、投稿修订和审稿意见仍可维护；冻结不等于禁止作者登录或投稿。

冻结固定参与者身份，公开署名与匿名设置继续遵循现有个人资料规则，不新增姓名快照。冻结切换不更改投稿、公开状态或上传窗口；解除冻结也不自动重新打开原本关闭的业务窗口。

## 展示资料与存储模型

建议新增 `work_presentations`，以 `segment_id` 为主键并关联 `schedule_segments`，实现每坑位最多一行。有需要才创建空白草稿，不要求提前给每个空位创建行。复用该坑位已有作品的 `draft_id` 作为关联及现有 `/works/:workId` 地址；编辑不变更坑位或作品归属。更换作者后如已有展示资料，须由管理员人工核对，不能自动把旧作者的资料套给新人。

| 字段 | 建议含义 |
| --- | --- |
| `segment_id` | 主键，坑位关联 |
| `draft_id` | 现有作品容器关联，保持详情地址兼容 |
| `title`、`summary` | 管理员维护的展示标题和简介 |
| `work_type` | 沿用现有作品类型 |
| `thumbnail_key`、`thumbnail_alt` | 独立预览图与图片说明 |
| `display_kind` | `gallery`、`markdown`、`bilibili` 三选一；空草稿可暂不选择 |
| `content_json` | 与形式对应的正文数据，只有当前一种形式 |
| `source_url` | 公开原作链接，沿用 HTTPS 校验；图片和文章可选，视频必填 |
| `published_at` | 是否已由管理员公开；NULL 表示草稿或已撤下 |
| `created_at`、`updated_at` | 创建及最近保存时间 |

图片列表存成该行中的有序数组，不为每张图新增业务表。D1 保存文本及对象键，图片字节存 R2。正文使用可辨别的类型并在服务端校验，不接受任意 HTML 或 iframe 源码。

预览图是逻辑上的坑位展示图，与正文第一张图独立。管理员可上传预览图，也可选择图片集中的一张复用。默认可不填，缺图使用现有文字封面。未公开作品允许在公开排期展示预览图、标题和简介，但正文及图片集其余图片须保持私有；后台对此清楚说明。

资料只有当前一份：保存未公开资料不会公开；保存已公开资料即更新观众看到的内容。预览尚未保存的修改后再决定是否保存，不新增草稿与线上双副本或编辑历史。普通网络失败提示重新读取、核对和人工重试。

## 三种展示形式

### 图片集

管理员批量上传图片，调整顺序、移除图片并填写图片说明。首版按顺序阅读，保持图片比例并适配移动端；不新增独立灯箱或图片编辑器。建议接受 JPEG、PNG、WebP、GIF，单张上限 20 MiB，由服务端校验大小与真实图片类型。

复用 Worker 到 R2 的现有基础，图片采用受限大小的普通上传，不照搬用于 500 MiB 投稿文件的分片状态与记录表。对象键限定在展示目录内并由服务器生成，不能指定审核附件对象键。

### Markdown 文章

管理员可粘贴、编辑或导入 UTF-8 `.md` 文件；原始 Markdown 存 D1，管理预览与公开页面共用渲染器。支持标题、段落、列表、引用、链接、表格及脚注，不执行 HTML、脚本或内嵌 iframe。首版只做文本编辑与预览，不增加文章内图片附件管理；需要图片集的作品选择图片集形式。

### Bilibili 视频

管理员填写完整 B 站视频链接，解析并保存 BV 号及可选分 P 信息，由系统生成 `player.bilibili.com` iframe，默认不自动播放并支持全屏。保留前往原作页面的链接。首版只支持 B 站视频，不实现任意站点嵌入。

切换形式前提示当前正文会被替换；表单未保存时不修改服务器记录。

## 手动公开及现有流程调整

公开资料的唯一来源改为新展示资料表。管理员的“公开／撤下”写入新表的 `published_at`，时间表仍使用现有排期数据；详情与前后作品导航读取已公开的新展示资料。

手动公开要求该坑位有已具参与资格的作者及对应作品、完整作品当前审核状态符合已有通过规则、展示标题和简介完整、所选正文形式有效。预览图可选；图片集和文章不强制填写外链。建议保留既有 `public_release_open` 作为管理员首次公开的开放控制，已公开内容的普通保存及撤下不受它限制。作者当天发布确认不作为本站手动公开的必填前置，由管理员核对最终版本。

`confirmPortalProjectRelease` 只保留作者按排期发布的确认及链接记录，不再写公开时间。移除 `publishConfirmedProjectIfReady` 的自动公开行为及其调用。审核通过不再复制标题、简介和类型到公开展示来源；投稿状态及历史审稿继续保存。作者修改原作链接也不直接修改管理员维护的链接。

原有 `project_drafts.published_at` 及旧双状态字段涉及数据库 CHECK；保留历史值，不重建作品主表。切换后所有线上公开判断以新表为准，避免两处公开状态混用。既有后台在“已公开作品需先撤下才可改为未通过”的校验应改读新的公开状态。

## 历史数据兼容

新增迁移不修改已应用的历史迁移、不更改 R2 审核对象。已有排期和作品 ID 保持。

仅对已有明确坑位关联的公开作品建立新展示记录，保留原公开时间、标题、简介、类型、原作链接及封面地址。由于旧资料没有本站正文，允许这批迁移记录暂时使用只含元信息及外链的兼容显示；管理员编辑正文并按三选一补齐。不为新作品增加第四种可选形式。

旧外部封面地址可通过兼容字段保留，管理员后续上传新预览图后替换。没有坑位关联的历史公开作品不能擅自丢弃或猜测关联：实施前只读统计；如存在，先列出数据和可行处理方式供用户决定，不能据此扩展数据模型。

沿用已有特别席位规则：特别作品可以由管理员手动公开，进入作品集及详情导航，但特别席位不出现在公共时间表；现有测试已明确覆盖这种差异。本次不把“时间表隐藏”扩大为禁止公开作品，也不因维护展示资料而把特别席位加入公共时间表。匿名读取预览图时，特别作品须已手动公开，不能借预览图入口提前暴露。

## 界面与接口边界

沿用管理端作品审核详情，增加独立“展示资料”区域；审核档案与展示编辑分别保存。包括标题、简介、类型、预览图、原作链接、展示形式及对应编辑区、预览、保存、公开和撤下。列表增加展示准备及公开状态，便于主催逐坑位整理，不重做整个后台。

展示模式下时间表保留当前排期布局，改为面向观众的浏览内容，去掉报名、占位和换位引导。待公开坑位显示作者、时间及已保存的预览资料；已公开提供正文入口。作品详情沿用现有页面壳、署名和前后导航，正文按形式渲染。预览图用于列表／卡片，不强制在正文顶部重复一次。

建议新增独立数据模块 `worker/data/work-presentations.ts`、路由模块与共享类型，不把新正文维护塞回投稿模块。管理员入口按坑位定位展示资料；公开详情继续按既有作品 ID 定位。

接口建议：

- 排期管理：读取及修改当前排期的冻结状态，沿用现有管理员权限。
- `GET/PUT /api/admin/segments/:segmentId/presentation`：读取、保存当前展示资料。
- `POST /api/admin/segments/:segmentId/presentation/images`：上传展示图片，返回展示对象标识；管理员可读自己待保存的上传对象用于预览。
- `POST /api/admin/segments/:segmentId/presentation/publish` 与 `/unpublish`：手动公开、撤下。
- `GET /api/works` 与 `/api/works/:workId`：扩展现有响应以承载独立展示数据及排期冻结状态。
- 展示图片读取接口：匿名仅可读公开排期中明确选用的预览图，或已公开正文引用的图片；管理员可预览未公开图片。不得凭对象键读取审核目录或其他未公开素材。

管理员写入沿用现有身份、Origin 校验与错误反馈。图片响应正确设置内容类型，正文及接口不暴露投稿附件、对象键、审稿意见或联系方式。缓存不得让撤下的正文图片继续经公开缓存长期读取，首版采用保守的重新验证／不缓存策略，不新增缓存失效系统。未保存的上传对象不进入公开读取范围，首版不增加自动清理队列。

## 验证与交付范围

本轮设计不重验用户已完成验收的旧功能，也不扩成全站重构或生产发布。

实施复用已有真实 SQLite D1 夹具及 R2 测试基础，精简覆盖冻结后的关键写入拒绝、投稿与展示互不覆盖、三种正文的保存与公开读取、只有管理员能公开、未公开正文及审核附件不泄露、预览图独立公开范围、历史作品兼容。

使用相关既有检查与构建，文案和布局不新增永久测试。UI 默认最多桌面／手机截图，不运行浏览器自动点击、填表或交互 E2E。新增迁移只在本地验证；生产迁移、冻结生产排期、公开真实作品和部署须另按交付范围授权。
