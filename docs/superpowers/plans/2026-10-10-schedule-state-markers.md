# 时间表状态标记与短动画实施计划

> 执行时使用 superpowers:executing-plans 按任务顺序实现。由当前主 agent 直接完成，步骤使用复选框记录；验证遵循用户 AGENTS.md，不自动新增永久测试。

**Goal:** 在现有阿波罗排程结构中，让占用、选中、我的时段和当前接力更容易区分。

**Architecture:** 复用 `PublicScheduleEntry.status` 和现有选择状态。状态签、占用填充、选择装饰分别呈现，集中在时间表条目与已有样式文件内；顶部总览使用相同状态语言。保持当前数据接口、详情打开方式与时间轴布局。

**Tech Stack:** 现有 React、Motion、CSS／SVG；不新增依赖。

**Spec:** 用户已认可本轮“固定状态签、占用填充、选中定位括号”的构思，以及短促的选中、状态变更和悬停反馈。艺术参考：[NASApunk 调研](../../design/nasapunk-style-research.md)与[视觉素材和动画库调研](../../design/visual-materials-and-motion-research.md)；本计划不执行其中的其他页面建议。

## 全局约束

- 优先完成固定状态签、占用填充和选中定位括号。
- 保留现有标尺、时间轴、分列、真实时间间隔、追加坑位和背景图。
- 占用状态来自 `entry.status`；选中来自 `selectedId`；“我的”和“当前接力”继续来自各自 ID，互不替代。
- 文案复用 `scheduleStatusLabels`，作者、作品标题、时间与操作立即可读。
- 不改认领、交换、报名和详情逻辑；不可选择的时段仍可查看详情。
- 修改现有未提交的时间表文件时，保留此前入场描线与游标过渡，不覆盖其他工作。
- 动效不循环播放，减少动态效果模式直接呈现最终状态。
- 运行相关已有测试和构建；仅进行截图查看，不自动点击、填写表单或执行交互流程。
- 本次是展示层调整，不新增永久测试，不部署；阶段性提交按用户后续指令执行。

## 检查重点

1. 选中预留或确认时段后，原有占用纹理仍能分辨。
2. 作者名字和作品标题较长、手机宽度较小时，状态签不遮挡文字或造成横向溢出。
3. 首次加载、选择变化、定时刷新和身份信息更新，不误触发占用变更动画。
4. 选中、我的时段、当前接力可以同时出现，并保留各自标记。
5. 减少动态效果模式、动画中途切换状态与组件卸载，装饰层能回到正确状态。

这些点通过实现检查与相关截图查看；点击后的运动节奏留待 dev 预览手动观看，交付时说明实际验证范围。

## 任务一 状态签与占用填充

**文件：** `src/app/components/ScheduleBoard.tsx`、`src/app/components/schedule-board.css`。

**接口：** 保持 `ScheduleBoard` 和 `ScheduleTaskDetail` 的导出接口不变。在 `ScheduleBoard.tsx` 内提取局部 `ScheduleTask` 组件，接收 `entry: PublicScheduleEntry`、`missionStart: number | null`、`mine: boolean`、`inspected: boolean`、`current: boolean`、`ownName: string | null`、`onSelect: (id: string) => void`。它只负责单个按钮；时间间隔、列表 ID 和布局仍由原列表渲染。

- [x] 提取现有时段按钮，保留原文案、`aria-label`、`aria-pressed`、详情关联和点击行为。
- [x] 在作者与作品内容旁加入固定状态签，复用现有 `ScheduleStatus`；即使有作品标题，状态仍可见。状态签参与正常布局，手机可换行；无预告时去掉原本重复的状态行，保留空闲时段的选择提示。
- [x] 加入独立占用装饰层，`aria-hidden` 且不接收指针事件。预留使用约 10% 浅灰填充与疏斜纹；确认使用约 20% 连续填充；空闲保持空心，不可选择使用弱虚线和斜杠符号。
- [x] 填充覆盖现有按钮区域，不改变条目高度，不暗示新的持续时长。顶部 `.ops-window` 同步采用预留斜纹、确认连续填充的语言。
- [x] “我的时段”补充短双线，保留“我的”标签；当前接力继续有独立指示。
- [x] 分离选择装饰与占用底层，移除会覆盖占用纹理的整块选中底色。选中改为四角定位括号与节点强调，保留文字对比和键盘焦点轮廓。
- [x] 检查以上静态状态的叠加关系，确认顶部总览、标准时段与追加坑位使用一致规则。

**产物：** 静止画面能区分状态，选择标记不会遮住占用信息；下一任务只为这些装饰增加短过渡。

## 任务二 短促反馈

**文件：** 同任务一，不新增模块或数据接口。

**输入：** 局部 `ScheduleTask` 的真实 `entry.status`、`inspected` 和减少动态效果偏好。

- [x] 选中时，定位括号从外侧约 3px 收拢并显现，约 200ms；节点短暂提亮后稳定。保留顶部现有 220ms 游标移动。
- [x] 悬停时，边界与节点约 140ms 提亮，短引线轻微展开；按钮和文字不位移，选中的强调不被悬停覆盖。
- [x] 在局部组件中记录前一次真实状态，初值为首次渲染的 `entry.status`。只有状态值变化才触发占用动画，不根据对象引用、刷新次数或选择变化触发。
- [x] 变为预留或确认时，占用层从时间轴一侧向右展开约 300ms；变为空闲或不可选择时移除占用层。状态签和文案即时更新，动画只影响装饰。
- [x] 用现有 Motion 控制占用层的裁切进度。连续状态变化时停止旧动画，从正确状态开始；减少动态效果模式直接设置最终裁切，卸载时停止控制器。
- [x] CSS 选择、悬停与节点动画在减少动态效果模式关闭；已有 Vivus 入场描线保持原逻辑。

**产物：** 真实操作和状态变化有短反馈，自动刷新不会让整张表反复演出。
