# Works 背景任务轨迹方案与实施计划

状态：用户已确认，已实施。采用路线 A，保持独立演示与 SVG 模块边界。

后续确认与实施：用户要求删除背景说明文字，并确认加入地心惯性系与斜视投影。现已用原模型参数将轨迹、月球、L₄ 与机动方向按各自时刻转换，使用约 40° 透视斜视、深度明暗和球体遮罩；模拟仍为原平面模型。下文保留第一版方案记录，背景标签与旋转系投影要求已被此后续决定替代。

**目标：** 将 works 背景的三组静态变轨图，改为一条有起点、机动节点、当前进度和目的地的连续任务航迹，保持时间表易读。

**推荐路线：** 复用首页已验收的地球出发、月球辅助、地月 L₄ 到达轨迹，以 SVG 表现任务规划，以独立的压缩时间演示表现进度。沿用 React 懒加载和卸载清理，不新增依赖、后台接口或轨道求解器。

**执行方式：** 确认方案后由主 agent 在当前会话按步骤实施；本计划不授权委派、提交、推送或部署。

## 1. 现状与问题

正式入口 `src/app/components/observatory/scene.js` 调用实验目录的 `renderOrbit(..., 'maneuvers')`。当前图形包含转移椭圆、轨道平面变化和调相环，但三者没有共同任务、时间或状态，视觉上更像教学图集。

首页已有 `src/app/components/orbital-transfer.json`，由 `scripts/orbit-transfer/` 生成，包含轨迹采样、采样时刻和三次机动。`orbital-transfer.ts` 已有按物理时间插值的位置函数；其投影适用于首页，需要在 works 背景中重新布局。

该数据采用地月旋转坐标系，表示含月球附近动力机动的平面轨迹，到达理想 L₄ 时旋转坐标速度为零。它没有计算鸟船交会、对接或编队观测；不能把这些阶段当作已有求解结果。

## 2. 可行方案与取舍

| 路线 | 得到的效果 | 主要取舍 |
| --- | --- | --- |
| A：复用既有数值航迹，重新构图并添加任务状态（推荐） | 连续且有来源的地月任务，和首页设定一致 | 航迹形状受现有数据约束；需要为背景调整投影和留白 |
| B：手绘全新的任务示意航迹 | 构图自由，容易安排交会和观测环 | 只能作为概念图，无法沿用现有数值验收 |
| C：重新求解交会或编队轨迹 | 可表达更完整的飞行过程 | 需要新增目标运动、边界条件与数值验收，超出本次背景美化范围 |

本计划选择 A。重要边界：任务演示与接力排期独立；天线保持现有微动，不声称它与航行器方向有真实跟踪关系。

## 3. 画面设计

### 一条连续的任务线

任务顺序为：地球出发 → 月球附近辅助机动 → 向 L₄ 巡航 → 抵达鸟船目标区域。

用一条主轨迹取代现有三组图。保留地球、月球、L₄ 与少量参考线，让路径变化有可理解的参照。末端用很小的鸟船目标符号和“鸟船 / L₄”标签表示叙事目的地，不在背景再建一艘三维空间站。

轨迹按同一旋转坐标系投影；构图只作统一旋转、等比例缩放和平移。禁止逐段扭曲航迹、用装饰曲线连接不连续节点，或混入惯性系路径冒充同一坐标系的备选航迹。线条密度过高时优先删除参考线。

### 层次与构图

- 主轨迹从桌面左侧较低位置出发，经上方月球区域，转向中部偏右的目标区域。具体旋转角和缩放以实际轨迹投影截图调整，目的地与天线轮廓保留间隙。
- 时间表文字附近尽量留白；保持现有背景层和 `pointer-events: none`，不增加浮层面板。
- 未来航段用暗色细虚线，已完成航段用稍亮的细实线；当前航行器为 3–4 px 小型方向标记，避免大片光晕。
- 参考几何再暗一档，仅保留必要的地月关系和目标定位。第一版不画没有数据来源的“备选方案”。
- 三个机动节点采用小圆点、短刻线与 `01 出发`、`02 月球辅助`、`03 到达`；常驻标签不超过六项。
- 图角落保留“任务演示 / 时间压缩”短说明，明确背景的播放状态与真实接力状态相互独立。
- 手机端保留主轨迹、天体、当前标记和三个短标签；去掉次要参考线。统一缩放与平移，确保主要节点仍可见，不缩小字号来塞入桌面全部细节。

## 4. 动态节奏

第一版演示周期暂定 **120 秒**，作为视觉参数，不对应真实任务时长。

| 播放阶段 | 时长 | 表现 |
| --- | --- | --- |
| 准备出发 | 8 秒 | 固定在出发点，出发节点渐亮，完整计划航迹已可见 |
| 转移飞行 | 100 秒 | 按既有采样时刻推进航行器，已飞行部分逐步转为实线 |
| 到达停留 | 8 秒 | 固定在到达点，到达节点与目标符号稍亮 |
| 循环过渡 | 4 秒 | 当前标记、进度覆盖线和状态淡出，再在起点恢复；底图始终保留 |

转移飞行采用整段任务统一的时间压缩比例，不按 SVG 路径长度匀速，也不将每段分配相同时长。月球附近运动较快属于采样结果；若可读性不足，优先调整整体周期，不任意改写局部飞行时间。

经过三次机动时显示局部方向提示，平滑淡入淡出约 2 秒；方向只采用已有数据中的机动向量，不随意画速度或推力箭头。当前位置附近可显示一个简短阶段名，省略虚构燃料、遥测、倒计时等数值。

第一版省略动态通信链路。现在没有地面站位置、地球遮挡和天线指向模型，画“通信窗口”容易产生错误含义；天线微动已经提供地面观测的视觉呼应。

减少动态效果时展示一张固定的月球辅助后巡航快照，隐藏演示中的阶段切换和循环过渡。页面隐藏或背景离开视野时暂停，恢复时从暂停位置继续，不补播时间。

## 5. 文件职责与边界

| 文件 | 计划职责 |
| --- | --- |
| `src/app/components/observatory/mission-orbit.ts`（新增） | 导入既有 JSON，定义 works 投影、时间插值、分段进度与阶段；不读取排期或系统日期 |
| `src/app/components/observatory/mission-orbit-scene.ts`（新增） | 创建任务 SVG、更新少量动态元素、管理暂停与清理；返回卸载函数 |
| `src/app/components/observatory/scene.js`（修改） | 将现有静态轨道挂载切换为任务 SVG，合并轨道与天线清理函数 |
| `src/app/components/schedule-board.css`（修改） | 轨迹层次、标记、标签与手机简化样式，延续已有背景布局 |
| `src/app/components/observatory/mission-orbit.test.ts`（新增，少量） | 覆盖新演示时间映射和阶段边界，不重复轨道求解器的验收 |

数据流：既有轨迹 JSON → works 时间与投影模型 → SVG 表现 → 背景挂载入口。首页的 `orbital-transfer.ts` 及既有轨道资产生成流程保持原职责，不为了背景改动它们的接口。

拟定接口：`missionFrameAt(playbackSeconds: number)` 返回当前位置、已完成的航段及当前航段进度、阶段和机动提示；`mountMissionOrbit(container: HTMLElement): () => void` 负责渲染与清理。精确返回类型随任务一落定，渲染层不得自行重算阶段。

动画上限 24 fps；SVG 在挂载时创建一次，只更新标记坐标、进度和状态属性。使用统一演示时钟；卸载时取消帧循环、媒体查询监听、可见性监听及观察器。
