# 创作者工作台单页整合简要计划

**目标：** 创作者在 `/portal` 内完成报名、查看审核、维护作品资料和调整排期，减少页面跳转。

**已确认方案：** 联系资料、创作计划与时段一起提交；提交后预留时段，通过后确认占坑，拒绝或撤回释放时段。审核通过后可换到空闲时段，或发起双方同意即生效的交换。工作台显示换期待办，并通过现有 Resend 渠道提醒。

**实现方向：** 沿用现有 React、TanStack Router 和 Workers + D1；前端以 `/portal` 为统一入口，将现有页面表单拆为职责清晰的区块。前端整合与必要的报名预留、交换请求、邮件提醒及并发一致性后端接口同步实施。

**已确认的样式与组件路线：** 以新版公共页面的黑灰底色、浅色文字和克制边框为视觉基准，统一基础 UI，工作台业务区块独立。公共站点、工作台和主催后台共享基础样式及通用组件，保留各自布局与信息密度。

前后端共享接口：

- `GET /api/portal/collaboration`：读取排期公开摘要和当前用户的换期请求，包含待审核账号。
- `POST /api/portal/application-with-segment`：一次保存联系资料、报名计划和预留时段；冲突时整体回滚。
- `POST /api/portal/application/withdraw`：撤回本人报名并释放时段。
- `POST /api/portal/swaps`：发起交换，保存后通过现有 Resend 渠道尽力发送邮件提醒。
- `POST /api/portal/swaps/:requestId/respond`：同意、拒绝或取消；同意时同时交换时段与作品关联。

沿用现有开放窗口作为截止规则；排期变更窗口结束后不能交换。时段或参与资格变化导致原请求失效。匿名设置始终应用于其他作者可见的名字，联系资料仅供本人及主催查看。邮件仅提醒登录工作台，不提供免登录确认动作。

实施基线：`npm test` 通过；永久测试仅用于关键行为和具体缺陷，样式与布局不新增测试。实际结果在完成记录中更新。

## 约束

- 保留公共页面和主催后台的既有页面结构。
- 页内区块独立管理表单、保存状态和错误，保存一个区块不能重置另一个区块未保存的内容。
- 刷新后恢复已保存数据；有未保存内容时，折叠区块不丢失输入。
- 前端展示遵循服务端权限和窗口状态，不能仅通过按钮状态放行操作。
- 采用自然、具体的文案，提交按钮说明结果，例如“提交报名并预留时段”。
- 不新增依赖；不进行无关重构。
- UI 验证最多截图查看，不自动点击、填表或执行浏览器交互流程。

- 首次报名无需在个人档案、报名和排期页面之间切换。

- 独立保存、操作失败和局部刷新不会丢失其他区块的输入。

- 创作者流程中的按钮、字段、状态和反馈采用统一样式，避免新旧主题混用。
- 通用 UI 与工作台业务职责分开，已迁移区块不再保留重复的基础组件实现。
